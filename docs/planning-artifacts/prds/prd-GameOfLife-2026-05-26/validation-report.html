medium

RFC-005 computes the FR-1.3 warning count from the saved index only — contradicts the PRD union rule

§ RFC-005:309 vs prd FR-3.12 / FR-1.7
The union reached RFC-005's FR-1.4 block (:310, "OR current initialGrid") and FR-1.7 list (:311, union), but its FR-1.3 line (:309) still reads usage.get(id)?.length ?? 0 — saved index only. PRD FR-3.12 requires the open Battle to count toward FR-1.3's "[N] Battle(s)", and FR-1.7 applies the union at "the FR-1.3 edit warning" surface. In the FR-3.12 flow (editing an organism from an unsaved "Current Battle" that places it), battles.list() lacks the unsaved battle, so the count returns 0 and the warning under-counts / fails to fire. Spec-vs-spec lag; the PRD is internally consistent — only RFC-005 lags (same pattern the C-2 round fixed for the delete check).
Fix: make RFC-005:309 read the same union as :310/:311 (saved index ∪ live initialGrid, deduped by battle id). Optionally tighten the PRD FR-1.7:159 "backing FR-1.3 and FR-1.4" phrasing that likely seeded the drift.
low

FR-1.4 remedy message doesn't cover the union edge it protects

§ FR-1.4 lines 133–134
When a saved open Battle's organism is live-erased (unsaved) but still blocked by the saved index, neither remedy fits: "erase from the current grid" doesn't apply (already erased), and "remove from those Battles / delete the Battles" points at a Battle already erased from. The only real remedy — save the Battle to persist the removal — is unstated. Soft dead-end (deleting the Battle also unblocks).
Fix: add a remedy branch: when the sole blocking usage is the open, already-saved Battle whose live grid no longer references the organism, instruct "save this Battle to persist the removal, then try again."
low

FR-8.4 "unmodified default" predicate under-specifies which fields count

§ FR-8.4 line 510 (+ FR-1.5)
The suppression enumerates modification as edits to "rules, color, or name," omitting the Dominance value (FR-2.2) and aging toggle (FR-2.4). Read literally, editing only Conway's Dominance or aging would still count as "unmodified" → warning suppressed → that edit silently discarded on import. Compounding: FR-1.5 never pins Conway's Dominance, so the baseline for that field is undefined.
Fix: state the comparison covers all editable fields (name, color, Dominance, aging toggle, rules) — a deep-equality against the seeded default — and pin Conway's default Dominance in FR-1.5 so the baseline exists.
