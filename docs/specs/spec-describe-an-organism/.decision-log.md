## 2026-11-01 — Review fix: `maxAge` defined in engine terms (independent review, PR #116)

- **Finding:** `maxAge` was "highest cell age reached" with no definition of age. The engine births cells at age 0 and saturates age at `max(7, highest age literal + 1)` (`maxRelevantAge.ts`, `conflictPhase.ts`), so Seeds measures 0 (E2 expected 1) and Conway measures a saturated 7 on every soup, a buffer cap that an explanation would have read out as a lifespan. B7 was ambiguous for the same reason.
- **Fix:** `behaviour-facts.md` defines `maxAge` in the engine's age and reports a saturated value as `≥ N`. E2 expects 0, E1 may cite the saturated `≥ 7` only as "outlives the run", and B7 expects ages 0–4. The mock's Explain scenario cited `maxAge: 184`, impossible under saturation, and now cites `≥ 7`.

## 2026-11-01 — Review fix: the zero-backend override is surfaced (PR #116)

## 2026-11-01 — Review fix: B12 uses the shared `oscillation` measure (PR #116)

- **Finding:** `eval-cases.md` says shared measures follow `behaviour-facts.md`, whose `oscillation` is the smallest period 2–10 repeating the whole grid over gens 150–200 from the random soups. B12 instead looked for period 2 over gens 50–100 on a seeded blinker, a different input, window and scope, so the two had already drifted.
- **Fix:** B12 passes when the shared `oscillation` fact reads 2 on every soup and the population is above 0 at gen 200. No separate blinker seed. An organism that truly blinks forever (born on empty, no Survive rule) alternates a soup with its complement, so the whole-grid measure is the right one.

## 2026-11-01 — Review fix: CAP-3 claims a subset of traits (PR #116)

- **Finding:** CAP-3 had the model state "the traits it intends" across the whole vocabulary and treated any mismatch as a repair trigger and then `ok_mismatch`. For "Classic Conway" no model can predict whether a 30 % soup on 50×30 reads `shrinks` or `stable` at gen 100, so a correct Conway draft would have carried "may not behave quite as described". The four traits also say nothing about neighbour-count behaviour (B6, B9, B11), so the intent "matches the behaviour the user described" overclaimed.
- **Fix:** the model claims only the traits the prompt constrains, possibly none; unclaimed traits are never compared; a draft without claims never gets `ok_mismatch`. The intent is narrowed to population-level behaviour and cell lifespan. `eval-cases.md` lists which behavioural prompts imply a claim and which imply none, so the fake-model test and the eval have a fixed expectation. `failure-modes.md` and `behaviour-facts.md` say the same thing in their own words.

## 2026-11-01 — Review fix: `trend` bands and a B9 criterion (PR #116)

- **Finding:** `grows` needed 3× the initial population at gen 100, which on a 30 % soup is 90 % of the grid, and `shrinks` was "anything else that survives", so an organism that doubled was reported as shrinking. B9 had no pass criterion: "behaviour check against a fixed rival fixture" named no measurement.
- **Fix:** `trend` is five-valued with an explicit precedence: `dies_out`, `stable`, `grows` (≥ 1.5×), `shrinks` (≤ 0.5×), `wanders` (alive, none of the above). B5 keeps its own stricter 3× check, since "fills the dish" means nearly full. B9 now needs a Die rule on `occupantNeighborCount` with a lower bound ≥ 3 that fires in the rival run, every cell with ≥ 5 rival neighbours gone the next generation over 50 gens, and solo survival to gen 50 so a draft that simply dies cannot pass vacuously.

## 2026-11-01 — Review fix: language is person-judged, CAP-9 is structured (PR #116)

- **Finding 1:** B10, N2, the Shape line, CAP-4 and CAP-8 require output in the prompt's or description's language, but the eval header says behavioural cases are judged by the engine, never by an LLM, and the engine cannot judge language. CAP-8 also keyed language on `description`, which is optional in `OrganismSchema`.
- **Fix 1:** language is reviewed by a person wherever it appears, like name fit and explanation prose, and sits outside the numeric thresholds. B10 counts toward 10/12 on its growth check alone. CAP-8 falls back to the name's language when the description is empty.
- **Finding 2:** CAP-9's success line ("every behavioural claim cites a fact … claims nothing else") is checkable in code only if the output is structured. The mock's chips implied it, no constraint said it, and RFC-009 needs it for the response schema.
- **Fix 2:** a new constraint: the explanation is a list of tagged sentences (fact id + value, rule id, or warning id); an untagged sentence or a wrong or unknown fact is `invalid_output`. CAP-9's success, `failure-modes.md` and the Explain header now speak of tags.

## 2026-11-01 — Review fix: `needsTarget` for `organismType` rules (PR #116)

- **Finding:** the rival run fires only for `cellState: occupied` and `occupantNeighborCount` conditions, with `conways-classic` as the only rival. A hand-built organism with a rule targeting a specific library organism (`organismType`, Decision C.2) would therefore be told the rule never fires, a false warning on exactly the organisms CAP-9 exists to check. The no-`organismType` constraint covers generated organisms only.
- **Fix:** such a rule is reported as `needsTarget`, never `neverFired`, and the explanation says it applies only when that organism is in the battle. If the target is `conways-classic` itself, the rival run measures it. E10 added.

## 2026-11-01 — Review fix: model calls per request are bounded (PR #116)

- **Finding:** the schema-repair count was left to RFC-009, the trait repair added one more call, and the 15 s p95 had to hold over all of them. Unbounded, the budget could not be reasoned about or tested.
- **Fix:** at most three model calls for a CAP-1 request (first, one schema repair, one trait repair) and two for CAP-5/8/9 (first, one schema repair). A second schema failure is `invalid_output`. `failure-modes.md` no longer defers the count.

## 2026-11-01 — Review fix: refine and "Try again" on a hand-edited draft (PR #116)

- **Finding:** nothing said whether a CAP-5 follow-up sees the user's hand edits to the draft or only the last generated one, nor what "Try again" does to those edits behind the unsaved-changes guard. R1 and R2 start from untouched drafts. The answer changes the request payload, so RFC-009 needs it.
- **Decision (proposed by the review, confirmed by Sidiar 2026-11-01):** refine works on the draft as it stands, hand edits included, because the user is refining "this organism"; "Try again" regenerates from the prompt alone and replaces the whole draft, asking first when the draft has hand edits, the same pattern as "Use as description". The CAP-5 model input is the open organism plus the session's AI history. R3 pins that hand edits survive a refine.

## 2026-11-01 — Review fix: what a "visitor" is for the rate limit (PR #116)

- **Finding:** a per-visitor rate limit needs an identifier, and the SPEC promised metadata-only records for a children's audience without saying whether that identifier is an IP address (personal data under GDPR, even hashed) or an anonymous token. That is a privacy choice for the spec, not the RFC.
- **Decision (proposed by the review, confirmed by Sidiar 2026-11-01):** the visitor is an anonymous random id minted in the browser and kept in localStorage, device-local like settings (Decision F). No IP address is stored or logged; an in-memory IP throttle for the window only is allowed. The CAP-7 records and GoatCounter events do not carry the visitor id. Clearing the token resets the limit, and the monthly cap is the backstop.
